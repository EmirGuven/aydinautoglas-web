# Design Audit — Phase A (FAZ A: Denetim)

Date: 2026-09-28. Read-only visual + code audit. No application code was changed in this phase.

## 1. Scope & method

- **Screenshots**: `docs/design/before/*.png` — 45 full-page PNGs at 360px, 768px, 1280px viewports, captured with a throwaway Playwright script (chromium) against the running dev server (`autoglass` seed data, German locale).
  - Public: homepage `/`, service detail `/services/steinschlagreparatur`, branch detail `/branches/berlin`, blog list `/blog`, blog detail `/blog/winterreifen-check`, appointment flow `/appointment`, 404 (`/this-page-does-not-exist-xyz`). FAQ/testimonials/partners are covered inside the homepage full-page shot (partners block has no seeded partner logos, so it renders empty by design — see Phase 8 status note).
  - Admin (logged in as `e2e-admin@example.com`, owner role): dashboard `/admin`, pages list `/admin/pages`, homepage block editor `/admin/pages/<id>`, services list `/admin/services`, service edit modal, testimonials list `/admin/testimonials`, theme editor `/admin/appearance/theme`, settings `/admin/settings`.
  - Everything requested was reachable; no gaps.
- **Code review**: `app/components/blocks/*.vue` (all 18 block components), `app/components/ui/*.vue`, `app/layouts/default.vue`, `app/components/admin/*.vue` (Sidebar, Topbar, DataTable, Modal, FormField, Breadcrumb), `app/layouts/admin.vue`, `app/assets/css/main.css` (theme tokens).
- **Note on the `web-design-guidelines` skill**: it was not present in this environment's available-skills list, so this audit was done as a direct manual code + screenshot review instead (structure below mirrors what such a skill would typically check: hierarchy, type, color/contrast, spacing, repetition, mobile, a11y).

## 2. Findings

### Visual hierarchy

- **Hero has no dominant focal element** (`app/components/blocks/Hero.vue`). When no editor-chosen background image is set (true in the current seed — `docs/design/before/public-home-1280.png`), it falls back to a plain dark-navy (`bg-secondary`) rectangle with a faint dot pattern, centered text, and one pill button. There is no product photography, no illustration, nothing that signals "auto glass company" versus any other local-service business. **Files**: `app/components/blocks/Hero.vue`. **Priority: high.**
- **Service/branch/blog detail pages are single-column, top-aligned text blocks with no visual anchor.** `docs/design/before/public-service-detail-1280.png` and `public-branch-detail-1280.png` show a heading + 1-2 paragraphs in a narrow column, then a large empty white area — on desktop this leaves roughly 60% of the page as unused whitespace, not "breathing room" but genuinely empty. No hero image, no icon, no price badge (service has a `priceFromCents` field per CLAUDE.md but it isn't rendered on this page), no supporting visual. **Files**: `app/pages/services/[slug].vue`, `app/pages/branches/[slug].vue` (not opened line-by-line but confirmed via rendered output). **Priority: high.**
- **Admin dashboard has three stat tiles and then a large empty canvas** (`docs/design/before/admin-dashboard-1280.png`) — no charts, no recent-activity feed, no quick links, despite Metronic Demo1 (the stated visual reference) being a dense, information-rich dashboard. **Priority: medium.**

### Typography

- Only two weights appear to be in real use across public blocks: `font-bold` (headings) and default/`font-semibold` (body/labels) — confirmed in `Hero.vue`, `ServiceCards.vue`, `WhyUs.vue`, `HowItWorks.vue`, `Testimonials.vue`, `CtaBand.vue`, all of which use the identical `text-2xl font-bold sm:text-3xl` heading class. There is no distinct display/heading typeface, no size step between H2 and H3 beyond `font-semibold` vs `font-bold` at the same base size in several blocks. This reinforces the "generic template" read — every section's heading is visually identical regardless of the section's importance (compare the homepage's primary value prop heading to a minor "Our locations" heading — same treatment). **Priority: medium.**

### Color & contrast

- **Theme has exactly three brand colors** (`admin-theme-1280.png`): primary blue (`#...` solid blue), secondary near-black navy, accent orange — plus background/text. This is a workable minimal palette but is applied almost uniformly flat: every button is a solid pill in `primary`, every card is `bg-white border-slate-200`, every section alternates white/white (no secondary-tinted or accent-tinted sections to break rhythm) except the two hard-navy bands (Hero, StatsCounter) and one hard-primary band (CtaBand). Result: the page reads as "blue button, white card" repeated ~8 times down the homepage, which is part of the "generic/template" complaint. **Files**: `app/assets/css/main.css` theme token layer, all block components. **Priority: high** (directly evidences the brand-identity complaint).
- Accent color (orange) is used almost nowhere on the public site — only in the admin theme-editor's own "Featured" badge preview. It's a wasted third palette slot; the public site is effectively two-tone (navy + blue). **Priority: low.**
- Admin dark mode: `app/layouts/admin.vue` and `DataTable.vue` do carry `dark:` variants consistently in the files reviewed, so the cross-file "hardcoded light-only color" gotcha documented in CLAUDE.md appears to have been respected in these components — no new contrast bug found here.

### Spacing consistency

- Public blocks are highly consistent with each other (`py-12`, `max-w-5xl`/`max-w-6xl`, `mt-10` grid gap) — spacing *within* the public site is not the problem, monotony is (see below).
- Admin forms have inconsistent horizontal rhythm: the page-builder "Edit page" panel (`docs/design/before/admin-pages-editor-1280.png`) is a fixed ~480px-wide card floating in a much wider content area, leaving a large dead column to its right that no other admin screen has (list screens and the theme editor use full available width via a two-column live-preview layout). This makes `/admin/pages/<id>` feel like an unfinished/different screen from the rest of the admin, not a deliberate layout choice. **Files**: `app/pages/admin/pages/[id].vue`. **Priority: medium.**
- The block list at the bottom of the page editor (`Hero`, `Service cards`, `How it works`, …) is a bare list of text rows with `Edit`/`Delete` links and a small drag-handle glyph — no icon per block type, no preview thumbnail, no indication of which blocks are empty/misconfigured. Compare to the admin sidebar, which does use per-item icons. This asymmetry (icons in navigation, none in the one place — block list — where visual scanning matters most for a content editor) is a concrete inconsistency. **Priority: medium.**

### Component repetition / monotony

- **This is the most code-verifiable finding.** `ServiceCards.vue`, `WhyUs.vue`, `HowItWorks.vue`, and `Testimonials.vue` all share the *exact same structural template*: centered `max-w-2xl` heading/subheading block, then a `grid grid-cols-1 sm:grid-cols-2 lg:grid-cols-3|4` of items, each item being a centered icon-circle (or numbered circle) + bold title + gray description paragraph, with no other layout variant available. There is no alternating-side "zig-zag" layout, no featured/highlighted item, no differing card size, no image-led card variant. A site visitor scrolling the homepage sees the same visual rhythm four times in a row (Services → How it works → Why us → Testimonials, only interrupted by the Hasar-Schnelltest widget and the dark StatsCounter band) — this is direct, concrete evidence for the "monotonous, no layout variants" complaint. **Files**: `app/components/blocks/ServiceCards.vue`, `WhyUs.vue`, `HowItWorks.vue`, `Testimonials.vue`, `Partners.vue` (not opened but same pattern per naming/usage), `BranchFinder.vue`. **Priority: high.**
- Every card across these blocks uses the identical `rounded-button border border-slate-200 p-6 shadow-sm` (or no shadow) treatment — service cards, testimonial cards, branch cards are visually indistinguishable from each other except for their content, even though they represent semantically different things (an action you can click into vs. a static quote vs. a location). **Priority: medium.**
- Admin: every list screen (`admin-services-list`, `admin-testimonials-list`) is the same bare white card + plain `<table>` with underlined text links for actions (no icon buttons, no button-styled actions, no row status color beyond one badge type) — again consistent internally, but monotonous versus Metronic Demo1's denser, icon-button-driven row actions and toolbar. **Priority: medium.**

### Mobile-specific issues

- At 360px (`public-home-360.png`), the hero's three trust badges (`Kostenloser Ersatzwagen`, `Direkte Versicherungsabwicklung`, `2 Standorte in Deutschland`) wrap to three separate lines and, combined with the heading + subheading + button above, push the fold very low — a visitor sees almost nothing but text before needing to scroll, no visual reward for the "above the fold" hero space.
- The cookie-consent banner (`docs/design/before/public-home-1280.png` and `-360.png`) overlaps directly on top of the service-cards heading at initial load on every page — expected first-visit behavior, but worth flagging: on 360px it consumes the top ~15% of viewport height and its "Alle akzeptieren"/"Nur notwendige" buttons sit awkwardly close to the viewport edge with a 3rd row of controls (branding icons "☁ 34ms ⏱") from what looks like a dev-only overlay (see Note below) — **this dev overlay artifact should not appear in production and doesn't reflect a real design issue**, but is called out so it isn't mistaken for one in later screenshots review.
- Admin at 360px: the sidebar is present in the screenshots taken (`admin-dashboard-360.png` etc.) — worth a follow-up check in the next phase on whether it's a collapsible off-canvas drawer or simply a squeezed fixed column, since CLAUDE.md's Phase 9 notes explicitly call out 360px admin support as an acceptance criterion; the audit screenshots alone don't show the interaction (a toggle click), only the static state.

### Accessibility

- No obvious regressions found in the reviewed files beyond what CLAUDE.md's Phase 9 notes already documented as fixed (labels, alt text, lazy-loading, ARIA labels on icon-only buttons). Icon-only "Edit"/"Delete" *text* links in `DataTable.vue` consumers are actually text, not icon-only, so no new labeling gap there.
- The `DataTable.vue` component supports `selectable` (checkbox column + `selectionChange` emit) but no consumer screen visible in the screenshots shows a bulk-action toolbar appearing when rows are selected — worth checking in the next phase whether this is dead code or simply not wired into any current list page.

## 3. Site-owner complaints — evidence check

1. **"Site looks generic/template-like, no brand identity."** — Confirmed. The theme is a flat 3-color palette (blue/navy/orange) applied almost uniformly (blue pill buttons, white bordered cards, one navy hero, one navy stats band); there is no logo mark beyond a text wordmark, no custom iconography style (uses default `lucide` outline icons at default weight everywhere), no distinctive typography, and the Hero's fallback background is a generic radial-dot pattern rather than anything auto-glass-specific. See `docs/design/before/public-home-1280.png`.
2. **"Hero section and CTAs feel weak/washed out, not conversion-focused."** — Confirmed. `Hero.vue` renders a single centered pill button (`bg-primary`, default weight, no size emphasis beyond `px-8`) against a dark, low-contrast-with-itself background (navy bg + white text + a barely-visible dot pattern) with no urgency/value framing beyond the badge list. `CtaBand.vue`'s CTA (`docs/design/before/public-home-1280.png`, "Bereit für Ihren Termin?") is a solid-primary band with a single white button — functionally fine, but visually identical in weight/format to the Hero CTA above it, so nothing in the page signals "this is THE most important action" over the other.
3. **"Content cards/blocks all look the same / monotonous."** — Confirmed with the strongest code-level evidence in this audit: `ServiceCards.vue`, `WhyUs.vue`, `HowItWorks.vue`, `Testimonials.vue` are structurally identical (see "Component repetition" above) — same grid, same icon-circle-then-text pattern, same card border/radius/shadow, with zero layout variant option in any of their block schemas.
4. **"Admin panel feels cluttered / inconsistent spacing / not faithful to Metronic Demo1."** — Partially confirmed, but the specific problem is closer to "sparse and inconsistent" than "cluttered": the dashboard (`admin-dashboard-1280.png`) is mostly empty space below three stat tiles (Metronic Demo1's dashboard is dense with charts/tables/timelines by comparison), the page-builder edit screen has an unused ~60%-width dead column, and the block list lacks the icon-driven visual scanning Metronic-style admin UIs use. ADR-0016 (per CLAUDE.md) already documents that the admin kit was deliberately built from scratch rather than copying Metronic's code — that's a legitimate constraint, but the *visual density and information architecture* gap (not code-copying) is what's driving this complaint, and is addressable without violating the "don't copy Metronic's code" rule.

## 4. Summary priority list (ranked, high first)

1. **[High]** Flat, uniform palette application across every section/card/button — no brand-specific visual identity (`app/assets/css/main.css`, all block components).
2. **[High]** `ServiceCards`/`WhyUs`/`HowItWorks`/`Testimonials` share one structural template with no layout variant — root cause of "monotonous" complaint.
3. **[High]** Hero has no strong visual/conversion focal point; fallback background is a generic dot pattern (`Hero.vue`).
4. **[High]** Service/branch detail pages are near-empty single-column text with large dead whitespace, no image/price/visual anchor (`app/pages/services/[slug].vue`, `app/pages/branches/[slug].vue`).
5. **[Medium]** Admin dashboard is mostly empty below 3 stat tiles — doesn't match the intended Metronic-style information density (`app/pages/admin/index.vue`).
6. **[Medium]** Admin page-builder edit screen (`/admin/pages/[id].vue`) has a large unused whitespace column, inconsistent with other admin screens' full-width layouts.
7. **[Medium]** Block list in the page editor has no per-type icons/thumbnails, unlike the sidebar which does use icons — inconsistent visual language within the same admin app.
8. **[Medium]** All cards (service/testimonial/branch) share identical border/shadow/radius treatment regardless of semantic role (clickable vs. static content).
9. **[Medium]** Admin list screens use plain underlined text links for row actions instead of icon buttons/badges, contributing to the "not Metronic-faithful" feel.
10. **[Medium]** CtaBand and Hero CTAs have equal visual weight, so no single action reads as the primary conversion goal.
11. **[Low]** Accent (orange) color is effectively unused on the public site — a wasted palette slot.
12. **[Low]** Typography has only two effective weight/size steps across all headings, flattening hierarchy between major and minor sections.
13. **[Low]** `DataTable.vue`'s `selectable`/bulk-select capability appears unused by any current admin list screen — worth confirming as dead code or wiring it up.
14. **[Info/non-issue]** A dev-only overlay (Nuxt DevTools indicator, "☁ 34ms ⏱") appears in the captured screenshots near the cookie banner — not a real design bug, exclude from any before/after visual comparison in later phases.
